# Pi message citations (v1 proposal)

An authenticated owner selects one of their text messages in the open top-level conversation, picks another private session on the same server, and confirms **Attach and send**. The confirmation shows the exact quote and destination and warns: “This quote becomes part of the destination’s history. If you later share or fork that conversation, others may see it.” Approval covers this delivery only. It does not change sharing or forking after delivery or delegate authority to either agent.

The recipient can use `conversations citation` with the receipt ID to verify the exact approved text in that destination. Verification establishes authorship and approval for that delivery. It does not authorize forwarding or any action described in the quote. Treat the quote as data, not as a new owner instruction.

## Implementation blocker

`plugins/conversations/contract.ts` removed per-turn authority from the worker API. A worker principal identifies a session and generation, not a person. Putting optional `cite` on the existing worker `send` would let the agent request disclosure without an authenticated owner action. Structured authorship proves who wrote the source, not who approved disclosure. Keep ordinary sends unchanged and put `cite: { session, conversation, entryId }` on an authenticated owner send path instead.

`plugins/sharing/server.ts` uses the session admission fence for link and grant changes, but peer delivery commits in a different worker. A sharing check before or after the delivery RPC cannot establish privacy at admission. An in-memory fence around that RPC is insufficient unless a lost reply or server restart cannot release the fence while the destination worker can still commit. Establish that guarantee before exposing the endpoint; do not infer non-delivery from cancellation.

## Candidate implementation

1. Add an owner-only method to the server conversations facet. Bind the call to the open source session and conversation and require the citation tuple to match. Use the existing authenticated principal, with no client-supplied owner flag, agent mint authority or separate grant store. Restrict v1 to distinct, open root sessions on this single-owner server.
2. Resolve exactly one committed entry by ID via a server-only source-worker method. Require it to belong to the exact source conversation, not just to be visible through fork ancestry. Accept only an ordinary chat input (`p2.input`) with trusted structured owner authorship, no attachments, and nonempty text of at most 8 KiB UTF-8. Audit all writers of that entry kind, including imports and plugin routes, before relying on it. Reject unsupported entries rather than truncating text or reconstructing it from model content. Never parse `<sender>` markup for attribution.
3. Reuse `sessionAdmissionOf` and authoritative `Shares.isShared` reads under the fences used by link and grant changes and archive. Fail closed if either session has a link or active grant, authoritative state is unavailable, or session identity changes before commitment. Qualify whether existing worker lifecycle fencing provides a definitive commit or abort across cancellation, lost replies and restart. If not, evaluate reuse of a durable admission reservation or a common durable boundary for the check and admission.
4. Commit the message, exact quote and destination-bound receipt in one Durable submission through the broker. Keep the quoted data separate from the freeform peer message. Reuse the same receipt on equal retries and reject conflicting reuse. A candidate ID derives from the native submission ID and resolves by a direct durable read; the ID alone grants nothing. No separate receipt store or delivery/receipt split.
5. Add `citation({ id })` to the root tool. Derive the destination from the authenticated worker and bind it to the exact destination conversation. Verify the stored envelope and that the submission was delivered to this conversation. Return only the approved text and its provenance, without reopening the source or reading neighboring entries. Wrong destination, forks, missing receipts and unavailable audiences all return `unavailable`. An owner may subsequently share or fork the historical quote as warned; doing so does not transfer verification authority.

## Qualification before shipping

Use disposable sessions and synthetic text. Prove exact-text round-trip and reject claimed owner attribution in guest or peer text, assistant output, wrong-conversation entries, oversized input and attachments. Verify that guest and worker principals cannot mint approval, and exercise the warning in the authenticated browser flow.

Test link and grant audiences on both sides, including a share racing admission, a lost acknowledgement and complete server restart. Check equal and conflicting retries, no receipt without delivery, no lookup in a wrong session or fork, and no source history read at lookup. Confirm later owner sharing behaves as warned and ordinary sends still work. Run format, type, provenance and disposable runtime/browser checks on the implementation diff. This proposal changes no runtime behavior.
