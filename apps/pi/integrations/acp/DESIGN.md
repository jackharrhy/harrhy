# Agent delegation in Pi

**Target:** One task API and one run lifecycle. Local Antigravity and Cursor are ACP agents (`agy acp` and `agent acp`); Cursor cloud stays on `@cursor/sdk` unless Cursor documents an ACP workflow that preserves cloud behavior. Pi delegates tasks, not model calls. The CLIs own local model routing and authenticate outside Pi; no OAuth token import or terminal scraping. [Antigravity ACP](https://antigravity.google/docs/ide/extensions/acp/) is Google's supported CLI path after [Gemini CLI consumer sign-in ended](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals).

## What this slice does

The optional foreground `acp_task` remains a disposable-workspace Antigravity proof: one prompt, one agent process, no persistence or automatic replay. The operator pins the executable and the workspace; tool callers can't set the command, flags, credentials or workspace. Existing Cursor local and cloud behavior is unchanged. No new Cursor tools are registered.

`runner.ts` owns stdio framing, initialization, session creation, streaming bounded assistant text, cancellation, and child cleanup. A session adapter can require setup before the prompt, reject mode changes, and cancel documented interactive extensions. It does not decide permissions: the transport selects only an unambiguous `reject_once`, otherwise cancels the turn. It offers no client filesystem, terminal or MCP servers. The new Cursor adapter is used only by a fixture. It uses [ACP v1 config options](https://agentclientprotocol.com/protocol/v1/session-config-options) to select `ask` or `plan` and verify the returned mode. It cancels `cursor/ask_question` and `cursor/create_plan`, rather than inventing a user answer or accepting a plan. [Cursor's ACP docs](https://cursor.com/docs/cli/acp) describe these modes and extensions, and document pre-authentication as an alternative to the `cursor_login` exchange. We don't initiate login or pass a key; an ACP authentication error tells the user to sign in separately. The fixture is a protocol example, not a transcript from a real Cursor CLI. It doesn't prove which mode payloads a particular CLI release sends.

## Cutover gates

- **Enforce local policy independently of ACP.** Denying permission callbacks does not confine a child or stop native tools that don't ask. `mcpServers: []` only keeps Pi from supplying servers: Cursor documents discovery of project and user `.cursor/mcp.json`, and its [CLI permission settings](https://cursor.com/docs/cli/reference/permissions) can pre-authorize tools. Do not enable Cursor ACP until a pinned CLI in an isolated home and workspace shows it can exclude ambient MCP, hooks, rules, and settings (or enforce an equivalent host boundary). Preserve real-path checks and the SDK's read-only tool allowlist semantics for ask/plan; edits still require the owner switch, and required sandboxing must fail closed. A mode label or a prompt asking the CLI to be careful is not proof. Apply the same containment review to Antigravity before moving it beyond its disposable proof.
- **Reuse the Cursor lifecycle, not a second supervisor.** Give the existing `runs.ts` manager and `agent-process.ts` worker a backend discriminator and map ACP text and settlement into their existing bounded partial/result records. Keep session-owned admission, caps, deadlines, cancellation, process identity and heartbeats, and the deduplicated completion wake. Package the runner with the surviving optional integration so installing it does not depend on a second plugin directory. Qualify each CLI's default model first; verify how model selection, tool/file activity, usage and sandbox status can be reported rather than guessing them.
- **Keep recovery routed to the original backend.** Preserve stored run IDs, ownership, wake subscriptions, and run-directory formats for in-flight SDK runs. Untagged records keep their old SDK interpretation; they can finish, be cancelled, or recover using their original IDs and policy. The SDK also keeps cloud repo/branch admission, edit policy, no automatic PR, and reattachment by cloud run ID. ACP `session/load` is capability-dependent and not reattachment to a live turn. Record an ACP session ID separately; never auto-replay a prompt or reinterpret an SDK ID as an ACP session. Show interruption and partial output when safe continuation isn't proven.

Next patch: exercise backend dispatch inside the existing detached worker with fake ACP, including deadline/cancel, restart observation and wake deduplication, without enabling real Cursor dispatch. Once the local policy and recovery gates have passed, route new local work through ACP in the single task API, retire the foreground proof and the legacy SDK-local *start* path, then remove legacy local recovery only after its records are drained or migrated explicitly. Users keep the same run IDs and status/result/cancel experience; any backend without safe resume must say so. No real login, metered prompt, deployment or cutover was performed in this slice.
